# Установка WristMind SelfHost

Это пошаговый путь от сервера до первого чата. Версия предварительная: финальная приёмка на чистом сервере и физических часах ещё ожидается.

## 1. Подготовьте сервер

Нужны Ubuntu 22.04/24.04/26.04 либо Debian 12/13 (amd64/arm64), Bash, curl и интернет. Python, Docker, Compose и системные утилиты скрипт устанавливает сам. Для установки пакетов нужны root-права; если запустили от обычного пользователя, появится стандартный запрос sudo. Пароль скрипт не сохраняет.

Ориентир базовой установки: 2 CPU, около 4 ГБ RAM и 10 ГБ свободного диска. Локальным embeddings потребуется дополнительное место. Проверка установщика оценивает ресурсы, но не гарантирует скорость.

## 2. Запустите меню одной командой

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/IvanSemenkin/wristmind-selfhost/main/install.sh)
```

Ручное клонирование и Git на сервере не нужны. Скрипт скачает исходники во временный каталог, проверит архив и запустит меню. Выберите каталог установки: `/opt/wristmind` для root или `$HOME/wristmind-server` для обычного пользователя. Можно указать другой абсолютный путь.

Выберите «Проверить требования», затем «Установить / продолжить установку». Запуск меню сам по себе не запускает установку. После выхода временные исходники удаляются; файлы установленной системы и данные остаются.

Во время установки нужен интернет. Панель, API, база и обработчик документов работают на одном сервере. Веб-поиск настраивается автоматически. Сохраните выбранный каталог: далее все команды используют его.

Если установка прервалась, не удаляйте файлы и данные. Снова запустите команду curl и выберите «Установить / продолжить установку», сохранив прежний каталог и параметры. [Подробности](docs/SELF_HOSTING_INSTALL.md).

Для любой дальнейшей настройки повторно запустите ту же команду, укажите каталог существующей установки и выберите нужный пункт меню.

## 3. Откройте первый вход

**В меню выберите:** 6 «Ссылка первого входа».

Ссылка одноразовая и даёт возможность создать владельца системы. Не публикуйте и не пересылайте её.

По умолчанию порт 8080 открыт только локально на сервере. На своём компьютере откройте второй терминал:

Для локального доступа с компьютера можно использовать защищённый SSH-туннель средствами своего SSH-клиента. Для обычного доступа с телефона и часов выберите пункт 4 меню и настройте HTTPS.

Откройте выданную ссылку через `http://127.0.0.1:8080`, сохранив её путь и фрагмент после `#`. SSH-сеанс должен оставаться открытым.

## 4. Настройте помощника

В мастере создайте владельца и пароль, выберите провайдера ИИ, введите API-ключ из его личного кабинета и выберите модель ответов. Проверка делает небольшой запрос по тарифу провайдера. Затем откройте чаты и отправьте первый вопрос.

Обычный текстовый чат требует модель ответов. Чтение документов, OCR и поиск по словам дополнительного API-ключа не требуют. Голос и понимание изображений можно настроить позже через внешние сервисы.

## 5. Настройте доступ с телефона и часов

**В меню выберите:** 4 «Домен / HTTPS / туннель».

Выберите домен с HTTPS либо туннель за NAT. Собственный домен необязателен. Для часов нужен доступный им HTTPS-адрес; `localhost` на телефоне означает сам телефон. [Настройка доступа](docs/SELF_HOSTING_ACCESS.md).

После HTTPS панель можно добавить на главный экран через браузер. `/main` открывает панель, `/talk` — интерфейс только с чатами.

## 6. Подключите Wear OS

Скачайте [Android-компаньон](https://github.com/IvanSemenkin/wristmind-selfhost/releases/download/android-v0.2.0-preview.1/wristmind-companion-0.2.0-preview.1.apk) из [релиза](https://github.com/IvanSemenkin/wristmind-selfhost/releases/tag/android-v0.2.0-preview.1) и установите на телефон с Android 11+. Разрешите установку из этого источника, если Android запросит подтверждение. Приложение часов встроено в компаньон; отдельный APK скачивать не нужно. В панели создайте код подключения устройства. В компаньоне введите HTTPS-адрес и этот код, затем пройдите мастер установки часов.

Не путайте код панели и код беспроводного ADB-сопряжения. После установки выключите отладку часов. [Полная инструкция](docs/COMPANION_SETUP.md).

## 7. Необязательные улучшения

Для локального поиска по смыслу:

**В меню выберите:** 7 «Локальный поиск по смыслу».

Скрипт скачает фиксированную модель, проверит её и назначит для поиска. Ключ и ручной выбор модели не нужны. Старые документы нужно повторно обработать. Локальные чатовые, vision и голосовые модели этот скрипт не устанавливает.

## Обновления и помощь

Повторно запустите единую команду и выберите **5 → 2 «Обновить автоматически»**. Скрипт найдёт последний готовый серверный выпуск для вашей архитектуры, скачает и проверит архив, создаст резервную копию и применит обновление. Вводить путь и SHA256 не нужно. Если версия уже актуальна, ничего не меняется.

Обновление сервера, backup и откат доступны только в терминале. Не очищайте Docker volumes ради исправления ошибки. [Обслуживание](docs/SELF_HOSTING_RELEASES.md), [проверка перед стабильным выпуском](docs/PUBLIC_RELEASE_CHECKLIST.md).


### Вход по IP без домена

Выберите в меню «Ссылка первого входа». Если внешний адрес ещё не настроен, установщик определит IP сервера автоматически (SSH-адрес или внешний IP через ipify) и включит доступ `http://IP:порт`. Для обычного порта 8080 разрешите входящие TCP-соединения на 8080 в сетевом экране сервера/хостинга. Покупать домен не нужно. HTTP не шифрует соединение; микрофон браузера требует HTTPS. Переключить доступ можно в пункте «Доступ по IP / HTTPS / туннель».

### Ночные обновления

После обновления через **5 → 2** в главном меню выберите **5 → 8**. Включите расписание, укажите время (по умолчанию **04:00**) и **свой часовой пояс**, например `Europe/Moscow`. Часовой пояс сервера может отличаться от вашего — проверьте предложенное значение. Расписание работает через systemd; можно изменить его или выключить в том же пункте.

В заданное время сервер проверяет новые выпуски и применяет только более новую готовую версию: SHA256, резервная копия, запуск и проверка здоровья, откат при ошибке. При обнаружении выполняющихся заданий обновление пропускается до следующей ночи. Выключенный ночью сервер не обновляется внезапно днём после включения. Логи и ближайший запуск показаны в меню. Веб-кнопок обновления нет.

Вход из одного браузера сохраняется до 30 дней без активности; при использовании срок продлевается. Выход и отзыв доступа требуют повторного входа. Повторный вход не создаёт ещё одну панель, если cookies браузера сохранены. Очистка cookies, другой браузер или другой адрес сайта считаются отдельным подключением.
