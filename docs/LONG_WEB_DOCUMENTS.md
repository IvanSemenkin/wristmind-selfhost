# Длинные веб-документы: чтение и ограничения

Этап 1, 12 октября 2026. Синхронизировано из основного проекта; production не обновлялся.

`open_web_page()` возвращает весь извлечённый HTML-текст в пределах лимита документа.
Превышение лимита — явная ошибка, а не сохранение первых символов. trafilatura
сохраняет Markdown-заголовки, абзацы и таблицы с `favor_recall=True`. Это не гарантия
полноты оригинала: скрытый JavaScript-контент, другие страницы книги и части,
отброшенные извлечением, автоматически не восстанавливаются.

| Переменная окружения | По умолчанию | Назначение |
| --- | ---: | --- |
| `WRISTMIND_WEB_OPEN_MAX_DOWNLOAD_BYTES` | 2000000 | Максимум скачанного/распакованного HTML |
| `WRISTMIND_WEB_HTML_MAX_DOCUMENT_CHARS` | 1000000 | Полный извлечённый HTML-документ |
| `WRISTMIND_WEB_MODEL_FRAGMENT_CHARS` | 12000 | Один фрагмент документа для модели |
| `WRISTMIND_WEB_HTML_MEMORY_MB` | 256 | Адресное пространство дочернего процесса HTML |
| `WRISTMIND_WEB_HTML_EXTRACT_SECONDS` | 12 | Время извлечения HTML после скачивания |

Извлечение запускается в отдельном процессе с Linux `RLIMIT_AS`; при таймауте или
отмене процесс завершается. Один event loop допускает одно извлечение одновременно. Открытий за поиск по
умолчанию два; настройка ограничена диапазоном 1–4.
Существующий worker по-прежнему исполняет один job за раз. Это лимит парсера, не
общий предел RSS контейнера; полный кэш и фрагменты также занимают память worker.
PDF сохраняет существующие ограничения размера, страниц и механизм OCR/Vision.

`DocumentView` читает произвольные блоки полного текста. `find` сначала возвращает
совпавшие блоки, затем соседние. Слишком большой диапазон `read` отклоняется до
копирования текста. Отсутствие точного номера не заменяется другим номером.

Кэш `RawWebSource` имеет `extraction_version=0` для всех прежних записей. Их длина
не считается доказательством полноты. Повторное обращение скачивает только нужный
документ; ошибка не превращает старый обрезанный кэш в полноценный. Новый документ
получает версию 1. `content`/`content_hash` прежней записи остаются исходным снимком;
`full_content` хранит обновлённый текст для инструментов чтения. Рабочие источники,
их файлы, чанки и embeddings не переписываются. Схема обновляется добавлением
колонок для PostgreSQL/SQLite, без массовой обработки документов.

Кэширование само по себе не создаёт INGEST или embeddings. Они создаются только
при принятии рабочего источника существующим механизмом. Очистка кэша, полный
журнал решений и автоматическое подтверждение всех глав пока не добавлены.
