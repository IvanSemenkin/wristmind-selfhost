# Админ-панель WristMind

## Назначение

Админ-панель — веб-интерфейс управления единственным экземпляром WristMind. Через неё владелец подключает веб-сессию, создаёт рабочие режимы, настраивает поведение помощника, загружает документы в базы знаний, ведёт чаты и подключает свои устройства.

Панель доступна как сайт WristMind. Основной рабочий адрес проекта: `https://wm.xspase.ru`.

Документ описывает фактически реализованный функционал текущей панели и API, а не будущие идеи.

## Модель доступа

В продукте один владелец-администратор. Обычные пользователи, роли, пользовательские панели и пользовательские коды исключены из интерфейса и публичного API.

Внутренняя запись владельца и связи `user_id` сохраняются в базе только для совместимости со старыми данными и внешними ключами. При запуске старые записи переводятся на единственного владельца; данные не удаляются.

## Подключение панели

При первом открытии сайт показывает экран подключения панели. Есть два способа:

1. **Секрет** — первичное администраторское подключение по bootstrap-секрету.
2. **Одноразовый код** — код, созданный в уже подключённой панели. Он используется для подключения часов или телефона владельца либо дополнительной веб-сессии администратора.

После успешного подключения сайт сохраняет сессию панели в локальном хранилище браузера. Токен устройства используется для запросов к API. Кнопка «Отключить эту веб-панель» удаляет локальную сессию; устройство на сервере при этом не отзывается.

## Общая оболочка сайта

На компьютере слева находится основная навигация, на телефоне — нижняя навигационная панель.

Разделы администратора:

- **Обзор**;
- **Чаты**;
- **Режимы**;
- **База знаний**;
- **Настройки**.

В верхней полосе есть:

- сообщение о текущем состоянии загрузки или ошибки панели;
- индикатор VPS API;
- индикатор зарегистрированного телефона;
- индикатор зарегистрированных часов;
- кнопка принудительного обновления данных.

Сайт адаптирован для большого экрана и телефона. Состояние, полученное с API, загружается единым обновлением: режимы, источники, чаты, устройства, модели, настройки и статистика.

## Раздел «Обзор»

Обзор показывает состояние рабочей области владельца и быстрые действия.

### Сводные показатели

- количество рабочих режимов;
- количество чатов;
- общее количество запросов к ИИ за всё время;
- количество активных подключений.

### Рабочие режимы

На карточке отображаются режимы владельца, их цвет и число источников в каждой изолированной базе знаний.

### Подключения

Показываются состояния:

- VPS API;
- Poco F6 или другого зарегистрированного телефона;
- Xiaomi Watch 2 или другого зарегистрированного устройства часов.

Для телефона и часов статус определяется по активной регистрации устройства. Отозванные устройства в число активных не входят.

### Быстрые действия

- **Быстрый чат** — создаёт универсальный чат для вопроса без выбора пользовательского режима.
- **Новый чат** — открывает выбор режима для постоянного чата.

## Раздел «Чаты»

Раздел содержит историю чатов владельца текущей панели.

### Создание чата

Кнопка «Новый чат» открывает список режимов. После выбора чат навсегда связывается с этим режимом. Название появляется автоматически после первого сообщения.

Кнопка «Быстрый чат» создаёт универсальный встроенный режим для общих вопросов. Встроенный режим не показывается в обычном списке пользовательских режимов и не редактируется как обычный режим.

### Список чатов

Для каждого чата отображаются:

- название;
- цвет и название закреплённого режима;
- дата последнего изменения;
- отметка «Универсальный» или «Режим закреплён».

Чат можно открыть или удалить. Удаление является скрытием записи через мягкое удаление: данные не должны физически уничтожаться сразу.

### Открытый чат

Внутри чата администратор может:

- загрузить историю сообщений;
- отправить новый текстовый вопрос;
- получать ответ потоково по мере генерации;
- видеть текущую фазу обработки;
- открыть полный сформированный ответ после завершения;
- вернуться к списку чатов;
- удалить чат.

Во время ответа панель показывает состояния вроде «Запрос принят», «Готовим контекст», «Уточняем поисковый запрос», «Ищем источники», «Проверяем источники», «Читаем источник» и «Формируем ответ». Для обычного ответа без веб-поиска часть фаз может быть пропущена.

Если поток временно оборвался, панель пытается дочитать итог через API задания. Уже принятый вопрос не должен превращаться в новый дубль благодаря постоянному `client_request_id`.

## Раздел «Режимы»

Режим — отдельное рабочее пространство помощника. В нём закреплены модель, системные инструкции, цвет, описание и своя база знаний.

### Список режимов

В списке отображаются:

- цвет режима;
- название;
- количество источников;
- признак «Отдельный контекст и RAG» или «Скрыт на часах»;
- кнопка видимости на часах;
- кнопка удаления.

### Создание режима

При создании задаются:

- название;
- описание;
- модель ответа из списка разрешённых моделей;
- цвет в HEX или через выбор цвета;
- системный промпт режима.

Новый режим сразу получает отдельные чаты и отдельную базу знаний.

### Редактирование режима

В карточке режима можно изменить:

- название;
- описание;
- цвет;
- выбранную модель;
- системный промпт.

Описание показывается при выборе режима на телефоне и часах. Системный промпт режима применяется вместе с общим системным промптом из настроек.

### Скрытие на часах

Кнопка с глазом переключает видимость режима на Wear OS:

- режим остаётся сохранённым в панели, его чаты и база знаний не меняются;
- при скрытии режим исключается из списка на часах и телефоне;
- повторное нажатие возвращает его в список.

Это визуальное скрытие, а не удаление.

### Удаление режима

Удаление выполняется через подтверждение. Режим и его источники скрываются из панели. Уже созданные чаты сохраняют историю и зафиксированное название режима. Операция не предполагает отмену из интерфейса.

## Раздел «База знаний»

База знаний разделена по режимам. Источник, загруженный в один режим, не становится источником другого режима.

### Выбор режима и сводка

В верхней части раздела можно выбрать режим. Для выбранного режима показываются:

- количество источников;
- сколько источников уже готово;
- примерный объём контекста в токенах;
- название текущего изолированного режима.

Есть локальный поиск по названию источника и имени файла.

### Добавление источника

Через кнопку «Добавить источник» открывается форма:

- выбор режима;
- название документа;
- выбор файла;
- способ обработки;
- подтверждение загрузки.

Поддерживаются PDF и изображения JPG, JPEG, PNG, WEBP в пределах серверного лимита размера.

Доступны два способа обработки:

- **Оцифровка OCR** — для текстовых PDF, книг и чётких сканов;
- **Vision-модель** — для фотографий заданий, схем, таблиц, рисунков и другого визуального материала.

После загрузки создаётся фоновая задача. Панель не должна ждать завершения обработки в одном HTTP-запросе.

### Список источников

Для источника отображаются:

- название и имя файла;
- способ обработки OCR или Vision;
- состояние «Обработка», «Готово» или «Ошибка»;
- число страниц;
- число фрагментов;
- дата добавления или обновления.

На компьютере используется таблица, на мобильном экране — карточки. Источник можно открыть или удалить.

### Карточка источника

В подробностях доступны:

- режим обработки;
- MIME-тип файла;
- количество страниц;
- количество фрагментов;
- оценка количества токенов;
- дата добавления;
- весь обработанный результат, разбитый на фрагменты;
- номер страницы, если он известен;
- размер фрагмента в токенах.

Именно показанный обработанный текст или результат Vision передаётся в контекст режима. Фрагменты загружаются страницами по 50; при наличии продолжения есть кнопка «Показать следующие 50 фрагментов».

### Повторная обработка и удаление

Для готового или ошибочного источника доступны:

- **Обработать заново** — удаляет старые фрагменты и повторно ставит исходный файл в очередь;
- **Удалить** — скрывает документ и его извлечённые фрагменты из базы режима после подтверждения.

При временном сбое провайдера задача оцифровки может быть автоматически возвращена в очередь и повторена worker-ом. Это позволяет исправить проблему маршрута или внешнего сервиса без повторной загрузки файла вручную.

## Раздел «Настройки»

### Общий системный промпт

Администратор видит текущую общую инструкцию и может перейти в режим редактирования. После сохранения общий промпт применяется перед промптом выбранного режима.

Общая инструкция подходит для правил, которые должны действовать во всех рабочих режимах.

### История в контексте

Можно указать количество последних сообщений чата, отправляемых модели в контексте. Допустимый диапазон — от 2 до 50 сообщений. В интерфейсе указано рекомендуемое значение 12.

Меньший лимит снижает расход контекста, больший сохраняет больше деталей диалога.

### Подключение устройства

Кнопка создаёт шестизначный одноразовый код. Код:

- действует 10 минут;
- отображается в отдельном окне;
- копируется в буфер обмена;
- используется для подключения часов, телефона или дополнительной веб-панели владельца.

### Отключение панели

Кнопка удаляет сохранённую веб-сессию из браузера и возвращает экран подключения.

## Что происходит с данными

### Изоляция режима

Каждый обычный режим имеет собственную базу знаний. Источники одного режима не используются как источники другого. Чат после создания получает фиксированный режим и не переносится между режимами из панели.

### Единый владелец

Чаты, сообщения, источники и устройства принадлежат одному владельцу-администратору. Внутренние ссылки на владельца нужны только для совместимости базы данных.

### Мягкое удаление

Удаление чата, режима или источника в текущем API реализовано как скрытие или отзыв доступа, а не как безусловное физическое удаление всех связанных данных.

### Идемпотентность

Создание чатов, отправка сообщений, загрузка и повторная обработка источников используют идентификатор запроса. Повтор после сетевого сбоя должен вернуть уже созданный объект, а не создать дубль.

## Основные административные API

Панель использует следующие группы маршрутов:

| Возможность | API |
|---|---|
| Первичное подключение администратора | `POST /v1/devices/admin/enroll` |
| Подключение по коду | `POST /v1/devices/enroll`, `POST /v1/devices/admin/enroll-by-code` |
| Выпуск кода устройства | `POST /v1/devices/pairing-codes` |
| Текущий пользователь | `GET /v1/me` |
| Устройства | `GET /v1/devices`, `DELETE /v1/devices/{device_id}` |
| Разрешённые модели | `GET /v1/models` |
| Общие настройки | `GET/PUT /v1/settings` |
| Статистика | `GET /v1/dashboard/stats` |
| Режимы | `GET/POST /v1/modes`, `PATCH/DELETE /v1/modes/{mode_id}` |
| Чаты | `GET/POST /v1/chats`, `POST /v1/chats/quick`, `PATCH/DELETE /v1/chats/{chat_id}` |
| Сообщения и поток задания | `GET/POST /v1/chats/{chat_id}/messages`, `GET /v1/jobs/{job_id}/events` |
| Источники знаний | `GET/POST /v1/knowledge`, `GET/DELETE /v1/knowledge/{source_id}` |
| Повторная обработка | `POST /v1/knowledge/{source_id}/reprocess` |

Все административные операции требуют действительного токена администраторского устройства. API дополнительно проверяет владельца чатов, сообщений и источников.

## Ограничения текущей админки

В текущей версии панели нет отдельного экрана для:

- просмотра чужих чатов от имени администратора;
- просмотра чужих баз знаний от имени администратора;
- редактирования Telegram Premium emoji из веб-интерфейса;
- ручного управления провайдерами и VPN;
- просмотра подробной системной телеметрии worker, очереди и затрат по каждому запросу;
- восстановления удалённого объекта из интерфейса.

Админка показывает рабочее состояние продукта и управляет настройками владельца. Инфраструктурные операции выполняются отдельно на серверах.
