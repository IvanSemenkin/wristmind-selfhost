# Поиск, исследование и источники

Этот документ описывает действующую систему поиска WristMind после пяти этапов переработки. Она отвечает только за веб-источники, найденные при работе **одного текущего чата**. Загрузка и использование материалов между разными чатами остаются отдельной существующей функцией базы знаний.

## Краткая модель

```text
вопрос пользователя
        |
        v
local-first router
  |       |        |        |
 none  chat_sources  web  deep_web
                         |
                         v
                 Referenced Source
                         |
             при необходимости автоматически
                         v
                   Working Source
                         |
                 только текущий chat_id
```

Цепочка заканчивается на `Working Source`. Автоматически найденный материал не переносится в межчатовую базу знаний и не создаёт второй механизм долгого хранения.

## 1. Неизменяемая постановка поиска

Перед поиском сервер строит **Request Anchor** из исходного сообщения. В нём фиксируются предмет запроса, задача пользователя, ограничения и явно указанные требования. Значимые фрагменты проверяются как фрагменты исходного вопроса: модель поиска не может подменить тему тем, что встретилось в выдаче.

Запрос к поисковой системе может переформулировываться для лучшего нахождения материалов, но это только техническая формулировка запроса. Она не меняет Request Anchor. При повторном поиске планировщик обязан указать одну закрытую цель: проверить факт, найти первоисточник, уточнить сущность, заполнить недостающий факт или перепроверить вывод. Свободных «исправлений постановки» в протоколе нет.

В итоговый prompt Anchor добавляется после непроверенного текста страниц. Поэтому веб-страница не может стать новой инструкцией и не может незаметно заменить исходную задачу.

## 2. Local-first router

Перед обращением к интернету компактный router получает вопрос и безопасный снимок доступного локального контекста: недавний диалог, материалы текущего чата, материалы режима и уже использованные ссылки. Он выбирает одно из четырёх действий:

| Решение | Поведение |
| --- | --- |
| `none` | Ответить без внешнего поиска. |
| `chat_sources` | Использовать и ранжировать материалы текущего чата. |
| `web` | Выполнить обычный ограниченный веб-поиск. |
| `deep_web` | Выполнить многошаговый поиск: при необходимости открыть страницы и сделать уточняющие запросы. |

Интернет не вызывается, когда доступных локальных данных достаточно. Флаги запроса остаются предпочтениями пользователя, но окончательное решение принимает router. Это исключает ситуацию, когда одна только кнопка «поиск» всегда уводит запрос наружу, хотя нужный текст уже есть в диалоге.

## 3. Режимы на часах

На Wear OS есть два режима:

| Режим | Что делает |
| --- | --- |
| `AUTO` | Передаёт выбор источников local-first router'у. Интернет может использоваться, а может не использоваться. |
| `RESEARCH` | Включает проверку и при необходимости доработку готового ответа. Источник выбирается всё тем же router'ом. |

`RESEARCH` не равен «обязательно искать в интернете». Если запрос решается по материалу текущего чата, проверка остаётся локальной. Проверяющий prompt учитывает тип работы: для текста следит за опорой на материал, для актуального факта — за проверяемостью и свежестью, для вычисления — за ходом и проверкой результата. Пользователю показываются только понятные статусы подготовки, поиска, проверки и доработки; внутренняя цепочка рассуждений не отображается.

## 4. Referenced Source

`Referenced Source` — лёгкая запись о результате, который был действительно передан модели как источник поиска. Она нужна для прозрачности и истории ответа, а не для RAG.

Для записи сохраняются URL, заголовок, сниппет, время получения, `chat_id`, идентификатор сообщения-ответа и идентификатор задачи. При необходимости может быть добавлено краткое резюме. Повтор одного URL в рамках чата не создаёт лишних одинаковых записей.

Referenced Source не содержит полного материала страницы, не индексируется как документ и не используется между чатами.

## 5. Working Source

`Working Source` создаётся только тогда, когда открытая страница содержит материал, который действительно понадобится для продолжения работы в этом чате: например, текст произведения, условие, глава, документация API или нужный фрагмент большого документа.

Перед созданием сервер консервативно проверяет соответствие страницы задаче. Готовые ответы, сочинения и шпаргалки не считаются первичным рабочим материалом только потому, что они упоминают тему. Затем сервер сохраняет очищенную исходную страницу, URL, заголовок, хеш и границы извлечения. Модель может выбрать фрагмент, но он принимается лишь в случае точного дословного совпадения с текстом страницы. При несовпадении безопасно используется вся очищенная страница — перефразированный текст не подменяет источник.

Working Source всегда имеет `chat_id` текущего чата. Он проходит обычную обработку и локальный retrieval, но при накоплении нескольких материалов они ранжируются по смыслу текущего вопроса, а не целиком добавляются в каждый prompt. Он не копируется в глобальное хранилище и не становится доступным другим чатам автоматически.

Когда источник найден и сохранён, ответ сразу показывает его заголовок и дословное начало: не более 1200 символов, с разрывом по границе предложения или абзаца, если возможно. Короткий материал может отображаться целиком. Для длинного материала полный текст показывается только по явной просьбе; предпросмотр никак не обрезает сохранённый Working Source и не влияет на дальнейший local retrieval.

## 6. Граница с существующей базой знаний

В проекте уже есть отдельная функция для материалов, которыми нужно пользоваться между разными чатами. Она сохранена без изменения. Если материал должен жить вне текущей беседы, пользователь использует именно этот существующий механизм загрузки и управления знаниями.

Новая система не создаёт отдельной сущности, API или перехода для долгого хранения результатов поиска. Её ответственность ограничена жизненным циклом веб-материала текущего чата: ссылка для истории и, когда это оправдано, рабочий текст для локального retrieval.

## 7. Надёжность и границы

- Поиск работает с ограничением времени, числа запросов и числа открываемых страниц.
- Если веб-поиск временно недоступен или не нашёл материалы, ответ помечает это и не выдаёт отсутствие источников за подтверждённый факт.
- Веб-страницы и RAG-фрагменты передаются модели как данные, а не как инструкции.
- Источники не показываются внутри ответа на маленьком экране часов; они остаются доступными через сервер и веб-панель.
- Автоматический Working Source не требует ручного действия на часах и не блокирует отправку следующих сообщений.
