# Пользовательская установка — конфигурация и запуск

Авторитетные файлы этой копии: корневой `compose.yaml`, `selfhost/Dockerfile`, `.env.example`. Старый `server/compose.yaml` сохранён как историческая конфигурация исходной установки и не используется новым сценарием.

## Доставка

- Основные сервисы — db, api и worker; установщик также автоматически включает SearXNG для веб-поиска.
- Образ собирается из существующих server и web: Node собирает панель, Python запускает существующий API и отдаёт статические файлы тем же адресом.
- Новая точка запуска — wristmind_server.selfhost_app:app. Worker и все API-контракты остаются прежними.
- Панель, `/assets`, `/health`, `/v1` доступны на одном порту. Deep links (`/talk/{id}`, `/chats/{id}`) возвращают index.html; неизвестные API-маршруты и отсутствующие файлы возвращают 404.
- Мастер `/setup` создаёт владельца по одноразовой ссылке из терминала, подключает провайдера и проверяет модель.
- База и приватные источники хранятся в двух именованных томах. Удаление/очистка томов в этот этап не входит.
- По умолчанию внешний порт 8080 привязан к loopback. До готовности безопасной первичной настройки/HTTPS публичное открытие требует явного выбора адреса привязки.

Команда установки, параметры и восстановление описаны в [SELF_HOSTING_INSTALL.md](SELF_HOSTING_INSTALL.md). Установка из исходников и готового проверенного пакета реализована; публичные релизы пока не опубликованы. См. [SELF_HOSTING_RELEASES.md](SELF_HOSTING_RELEASES.md).

## Требования и конфигурация

Docker Engine, Docker Compose plugin не ниже 2.24 (optional env_file), Linux. Первая локальная сборка пока требует доступа к реестрам Node/Python/контейнеров. Сборка версионированных пакетов реализована; их публикация и настоящая серверная приёмка ещё предстоят.

`.env.example` — шаблон с пустыми секретами. Compose отклоняет конфигурацию без пароля базы, bootstrap-секрета и token pepper. Пароль базы должен быть URL-safe; установщик этапа 3 генерирует hex-значения без перезаписи прежних секретов. Реальные ключи не входят в build context.

Текущая администраторская авторизация через bootstrap/одноразовый код унаследована от работающей версии. Она будет заменена штатным мастером/входом на этапе 4; этот этап не предоставляет её конечному пользователю как завершённый сценарий.

Для просмотра без расходов можно установить WRISTMIND_MOCK_PROVIDERS=true; настоящие провайдеры выключены лишь в этом режиме. Для рабочих ответов нужны ключи выбранных провайдеров и соответствующие настройки моделей.

## Опции

- Поиск: профиль `search`, WRISTMIND_SEARXNG_URL=http://searxng:8080 и уникальный SEARXNG_SECRET. SearXNG не публикует порт хоста. Включения профиля без этих настроек недостаточно для работающего поиска.
- Telegram: профиль `telegram`, WRISTMIND_TELEGRAM_BOT_TOKEN и WRISTMIND_TELEGRAM_OWNER_ID. Ключи заданы только в .env, контейнер использует тот же образ и том источников. Пока нет проверяющего настройки мастера.
- Домен/HTTPS и Cloudflare Tunnel подключаются командой `wristmind access` через отдельный Compose override. См. [SELF_HOSTING_ACCESS.md](SELF_HOSTING_ACCESS.md). Универсальная конфигурация не наследует частную маршрутизацию VPN/iptables исходной установки.
- Старый Android assetlinks.json удаляется из веб-сборки образа: подтверждение конкретного домена/подписи относится к будущему этапу приложений.

## Границы проверки

Compose config проверяется без доступа к Docker daemon. Локальная веб-сборка, маршруты StaticFiles и настоящий API проверяются отдельно. Успех этих проверок не заменяет сборку/запуск Docker-образа, PostgreSQL и профильных сервисов на чистой машине.

### Автоматический поиск в установках

Исходный Compose оставляет search отдельным профилем. Сам установщик теперь автоматически записывает COMPOSE_PROFILES=search, внутренний URL и случайный секрет в защищённый .env, поэтому обычная готовая установка запускает db/api/worker/searxng. Новый install-release использует ту же подготовку. Для старой установки доступна команда web-search; дополнительные профили сохраняются.
