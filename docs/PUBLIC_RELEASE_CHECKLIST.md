# Приёмка первого публичного выпуска

## Подготовка исходников

Не публикуйте унаследованную историю рабочего репозитория. В ней есть старые инфраструктурные конфигурации; отсутствие секретов в нынешних файлах не доказывает отсутствие секретов в прошлых коммитах.

```bash
python3 selfhost/public_source.py --output /tmp/wristmind-public-source
```

Команда создаёт **новый** каталог из разрешённых исходников и пользовательских документов. Не переносит `.git`, данные, `.env`, ключи подписи, Firebase-конфиги, APK, локальные настройки, старые серверные Compose/deploy-конфиги и legacy-модули. Ссылки и распознанные форматы приватных ключей/API-токенов останавливают экспорт; содержимое найденного секрета не печатается. Это ограниченная автоматическая проверка, а не полноценный аудит безопасности. Нестандартные секреты могут остаться: проверьте результат вручную и проверенным secret scanner перед публикацией.

В новом каталоге проверить код и документы; затем выбрать лицензию и создать новую Git-историю. Инструмент не выбирает лицензию, не создаёт коммит и не делает push. Основной проект и его история сохраняются.

Компаньон и Wear APK подписываются постоянным release-ключом, который хранится отдельно и резервируется безопасно. Публикуйте checksum APK и пакетов. Тестовые ключи и APK локальных проверок не являются публичными релизами. APK `android/panel` привязан к историческому домену; для произвольного self-host сервера распространяется веб/PWA, а не этот TWA APK.

## Локальные проверки экспортированной копии

```bash
cd web
npm ci
npm test
npm run build
cd ..
python3 -m pip install './server[dev]'
python3 -m pytest selfhost/tests -q
```

Сборка веба должна предшествовать API-тестам: они запускают настоящее приложение со статическими файлами.

Android: JDK 21, Android SDK; `:core:test :wear:testDebugUnitTest :phone:testDebugUnitTest :phone:assembleDebug :phone:lintDebug`. Никаких секретов основной установки для проверки не требуется. Тест соответствия соседней основной копии пропускается, если её нет.

## Настоящий чистый сервер — ещё не проверено

Это обязательная приёмка перед объявлением первого стабильного выпуска. Нужен новый Linux-сервер без данных исходного проекта; Docker/Compose, свободный порт и доступ к интернету. Пройти последовательность из README, записать версии ОС/архитектуру/ресурсы и реальные результаты в SELF_HOSTING_STATUS.md.

- [ ] `check`, `install`, health PostgreSQL/API/worker/SearXNG; повторный запуск не меняет секреты и данные.
- [ ] Одноразовый первый вход, пароль, реальный API-провайдер и обычный ответ; повторная bootstrap-ссылка отклоняется.
- [ ] Домен/HTTPS либо туннель за NAT; телефон открывает панель без предупреждения сертификата.
- [ ] Веб-поиск, загрузка текстового PDF и сканированного изображения, OCR, RAG по словам.
- [ ] Локальные embeddings устанавливаются и назначаются автоматически; повторная обработка источника, поиск по смыслу. Замер ресурсов/скорости на amd64 и arm64, где заявлена поддержка.
- [ ] Серверное распознавание с выбранным внешним провайдером; отсутствие speech/vision-модели даёт предусмотренное ограничение.
- [ ] Backup → update → health → rollback; восстановление в отдельную установку сохраняет чаты/источники/провайдеры. Не испытывать восстановление на единственной копии данных.
- [ ] Остановка сервера и сетевые ошибки показывают понятное восстановление; никакого удаления данных ради исправления.

## Настоящие часы — ещё не проверено

- [ ] Android-компаньон: ADB pairing по коду, connect по отдельному порту, правильный Wear OS и ограничение SDK.
- [ ] Установка подписанного APK, адресная probe/config/ACK, выбор именно установленных часов; токен не передаётся посторонним узлам.
- [ ] Переподключение, неверный код/порт, истёкший challenge, обрыв сети и отказ установки не оставляют мастер зависшим.
- [ ] Новая версия поверх старой сохраняет настройки/чаты; другой сертификат/старая версия отклоняются без автоматического удаления.
- [ ] Чат по прямому HTTPS; fallback через Wearable Data Layer; диктовка, потоковый ответ и источники.
- [ ] Выключенная отладка после настройки не мешает обычной работе.

До этих проверок корректный статус — «локальная разработка завершена, серверная и физическая приёмка ожидается», а не «готово и протестировано у пользователей».
