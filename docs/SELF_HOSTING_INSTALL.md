# Установка и настройка через меню

Все действия выполняются из одного меню. Запустите его на Linux-сервере:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/IvanSemenkin/wristmind-selfhost/main/install.sh)
```

Git и ручное клонирование не нужны. Исходники скачиваются по HTTPS во временный каталог; архив проверяется на обход путей, ссылки и размер. После выхода временные файлы удаляются. Запускать скрипт следует из доверенного репозитория.

## Требования

Linux, Bash, curl, Python 3.10+, Docker Engine с доступом текущего пользователя, Compose plugin 2.24+, timeout/coreutils и ss/iproute2. Проверяются 2 CPU, около 4 ГБ RAM и 10 ГБ свободного места. Docker и права доступа к нему настраиваются отдельно. Первая сборка требует интернета.

## Новая установка

1. При запуске выберите абсолютный каталог. По умолчанию `/opt/wristmind` для root или `$HOME/wristmind-server` для обычного пользователя. Чужие файлы и неизвестная прежняя установка не перезаписываются.
2. Выберите **1 «Проверить требования»**.
3. Выберите **3 «Установить / продолжить установку»**. Укажите HTTP-порт (по умолчанию 8080) и режим: обычный либо демо без ключей/платных запросов.
4. Дождитесь проверки здоровья сервисов. База, API с панелью и обработчик документов работают на одном сервере; веб-поиск настраивается автоматически.
5. Выберите **4 «Домен / HTTPS / туннель»** для доступа с телефона и часов. Домен необязателен; варианты описаны в [руководстве доступа](SELF_HOSTING_ACCESS.md).
6. Выберите **6 «Ссылка первого входа»**. Откройте её, создайте владельца, подключите провайдера и выберите модель. Проверка реальной модели оплачивается по тарифу провайдера.

Первоначальный HTTP привязан к loopback. До настройки HTTPS используйте защищённый SSH-forward для доступа с компьютера, как описано в [SETUP.md](../SETUP.md). Не открывайте незашифрованный HTTP в недоверенную сеть.

## Повторный запуск и ошибка установки

Снова запустите единую команду, укажите прежний каталог и выберите пункт **3**. Незавершённая установка продолжается с сохранением секретов и параметров. Готовая установка не пересобирается этим пунктом; обновления находятся в пункте **5**.

Чаты, документы, устройства и ключи не удаляются. При повреждении или отсутствии прежних секретов установщик отказывается генерировать новые поверх существующих. Одновременные операции блокируются. Проверка здоровья происходит внутри конкретного API-контейнера, а не по ответу постороннего сервиса на хосте.

## Остальные настройки

| Пункт | Действие |
| --- | --- |
| 2 | Состояние выбранной установки |
| 4 | Домен/HTTPS, туннель, локальный режим и проверка доступа |
| 5 | Версия, обновление, бэкап, восстановление, откат, удаление контейнеров и установка готового пакета |
| 6 | Одноразовая ссылка первого входа |
| 7 | Установить и назначить локальную модель поиска по смыслу |
| 8 | Настроить и проверить веб-поиск для существующей установки |

Для локального поиска ключ и выбор модели не нужны. Vision, чатовые и голосовые модели локально этим меню не устанавливаются. После настройки провайдеров и моделей в веб-панели доступны соответствующие функции.

## Границы проверки

Сценарии повторного запуска, отказа и восстановления проверяются локально с имитацией Docker. Настоящая сборка/запуск контейнеров на чистом сервере, HTTPS и физические часы ещё ждут финальной приёмки. Предварительный компаньон доступен в GitHub Releases; готовые Docker-пакеты сервера пока не опубликованы.
