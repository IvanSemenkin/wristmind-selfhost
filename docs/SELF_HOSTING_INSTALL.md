# Установка из исходников — этап 3

Разработка ведётся в отдельной копии WristMind-SelfHost. Это рабочий сценарий установки из локального дерева исходников, а не опубликованный пользовательский релиз. Установка проверенного готового пакета и обновления реализованы; команды описаны в [SELF_HOSTING_RELEASES.md](SELF_HOSTING_RELEASES.md). Публичные артефакты пока не выпущены. Не используйте рабочий сервер исходного проекта для испытаний.

## Запуск без клонирования

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/IvanSemenkin/wristmind-selfhost/main/install.sh)
```

Выберите каталог, затем проверку требований и установку. После установки пункт «Ссылка первого входа» выдаёт адрес мастера. Через это же меню доступны HTTPS, обновления/бэкапы, локальные embeddings и веб-поиск. Git не нужен; Linux, curl и Python 3.10+ нужны для загрузки, Docker/Compose — для установки. Установщик не устанавливает Docker автоматически.

Повторный запуск открывает меню для выбранного каталога и не удаляет данные. Исходники скачиваются по HTTPS в временный каталог; архив проверяется на обход путей, ссылки и размер. После выхода временные файлы удаляются. Скрипт загружается из текущей main-ветки доверенного репозитория: запускать только если доверяете её владельцу.

## Требования

Linux, Bash, Python 3.10+, Docker Engine с доступом текущего пользователя, Compose plugin 2.24+, timeout/coreutils и ss/iproute2. Проверяются 2 CPU, около 4 ГБ RAM и 10 ГБ свободного места. Установка Docker и выдача прав на него пока выполняются отдельно. Первая сборка требует интернета для получения образов и зависимостей.

Из каталога исходников:

```bash
./wristmind check --install-dir "$HOME/wristmind-server"
./wristmind install --install-dir "$HOME/wristmind-server" --demo
```

`--demo` включает существующие мок-провайдеры без платных запросов. Для реального экземпляра опустите параметр; ключи поставщика будут настраиваться мастером этапа 4. Без ключей полноценные ответы от настоящей модели пока недоступны.

Устанавливаются база, API с панелью и обработчик. Порт по умолчанию 8080, адрес http://localhost:8080/talk. Мастер `/setup` и пользовательский вход ещё не готовы; доступная панель пока сохраняет прежнюю авторизацию.

## Параметры

- `--install-dir`: абсолютный каталог вне дерева исходников. Путь с пробелами поддерживается. Чужие файлы, неизвестная прежняя установка и символическая ссылка не перезаписываются.
- `--port 18080`: собственный свободный HTTP-порт.
- `--bind 127.0.0.1`: безопасное значение по умолчанию. Для доступа к удалённой машине пока используйте SSH-переадресацию порта.
- `--bind 0.0.0.0`: явное открытие порта в сети. До этапов входа и HTTPS не открывайте его в интернет.
- `--timeout 180`: ожидание запуска/health, от 1 до 600 секунд; не ограничивает длительность сборки.
- `--resume`: продолжить незавершённую установку с прежними параметрами и секретами.
- `--domain`: поддерживается диагностикой `check`; команда `install` пока отклоняет его до этапа 5.

## Что сохраняется

В каталог атомарно копируется только необходимый код сервера и панели с конфигурацией сборки. Git-история, исходная `.env`, пользовательские данные, Android-код, node_modules и кэши не копируются. Символические ссылки в сборочном наборе отклоняются.

Генерируются независимые пароль базы, bootstrap-секрет и token pepper. `.env`, файл состояния `.wristmind-install` и журнал `install.log` имеют права 600, каталог установки — 700. Каждая установка получает собственное имя Compose-проекта, образ и именованные тома; разные экземпляры не используют одну базу по умолчанию.

Конфигурация читается как данные, не исполняется. Внешние переменные WristMind/Compose не подменяют установку. Известные секреты скрываются в журнале. Команда не выводит секреты на экран.

## Сбой и повторный запуск

```bash
./wristmind status --install-dir "$HOME/wristmind-server"
./wristmind install --install-dir "$HOME/wristmind-server" --resume
```

Повторный запуск завершённой установки ничего не пересобирает и не заменяет секреты. `status` показывает сохранённое состояние, а не подтверждает текущую доступность контейнеров. После ошибки конфигурация и данные остаются на месте; запуск отмечается как незавершённый. Автоматическое удаление контейнеров и томов не выполняется. При повреждённых секретах установщик отказывается работать, вместо генерации новых поверх старых.

Проверка здоровья выполняется внутри конкретного API-контейнера после Compose `up --wait`; сторонний сервис на хосте не может выдать себя за установленный API. Установщик блокирует одновременную установку в один каталог.

## Границы проверки

Сценарии установки, отказа, восстановления и повторного запуска проверяются локально с имитацией Docker. Конфигурация полученного каталога дополнительно проверяется настоящим Compose CLI без запуска контейнеров. По решению владельца сервер будет предоставлен только после реализации всех этапов. Итоговая проверка должна включить настоящую сборку образа, PostgreSQL, запуск сервисов, перезапуск и работу из браузера; она пока не выполнена.


## Первый вход и настройка

После install выполните `./wristmind setup-link --install-dir <каталог-установки>` и откройте выданную ссылку. Одноразовый код находится в фрагменте URL и удаляется из адресной строки после открытия мастера; он не попадает в HTTP access log. Создайте владельца с паролем от 12 символов, выберите провайдера и ключ, затем найдите модель или укажите ID вручную. Короткая проверка модели оплачивается по тарифу провайдера. Создайте первый режим, проверьте вопрос и откройте чаты. Новые подключения и модели добавляются в настройках панели.

Демо-установка показывает тестовый каталог и ответы без ключа и платных вызовов. До этапа HTTPS используйте loopback или SSH-forward. Не открывайте незашифрованный HTTP в недоверенную сеть.

## Домен и HTTPS

После установки терминал предлагает настроить внешний доступ или пропустить этот шаг. Позже используйте `./wristmind access --install-dir <каталог>`: локальный доступ, собственный домен с HTTPS либо Cloudflare Tunnel за NAT. [Инструкции и восстановление](SELF_HOSTING_ACCESS.md). `setup-link` после настройки использует сохранённый HTTPS-адрес.

## Веб-поиск

При новой установке настраивается автоматически, без ключа/ручного URL. Для существующего сервера после обновления до релиза с этой командой:

```bash
./wristmind web-search --install-dir /opt/wristmind
```

Команда активирует SearXNG и проверяет JSON-поиск из API; после «Готово» обновите панель. Если установлен другой поисковый URL, автоматическая замена запрещена. Поисковик работает внутри Docker-сети, исходящие запросы идут в интернет. Настройки поисковых движков взяты из SearXNG; ограничения/блокировки внешних поисковых систем могут влиять на результаты. [Документация SearXNG](https://docs.searxng.org/admin/installation-docker.html).
